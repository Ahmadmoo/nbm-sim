# nbm-sim

Camera-only Isaac Sim environment for **Next Best Motion (NBM) in event-based 3D reconstruction**.
A camera moves through a static scene under a six-axis body-twist command. The environment returns
synchronized events (generated by [EVIS](https://github.com/spikelab-jhu/isaac-sim-event-camera-plugin)),
RGB, calibration and known poses. Reconstruction, uncertainty and planning are external modules.

Implements the first deliverable of `NBM_Simulation_Specification.md` v1.1 (milestones M1–M3).

> **Status.** The pure-Python parts (motion, packets, recording, replay, metrics, EVIS wrapper) pass
> their test suite. The Isaac-side code has **not yet been run on Isaac Sim**. Run the acceptance
> scripts in §3 before using any result. No milestone is validated until they pass.

---

## 1. Tested software pair

| Component | Version |
|---|---|
| Isaac Sim | 5.1 |
| Isaac Lab | 2.3.x |
| EVIS (`dvs_gen`) | commit `d6fe479` (2026-07-10) |
| Python | the Isaac Sim Python (3.11) |

EVIS is written against Isaac Lab 2.x: the `HdrColor` annotator, torch outputs, and `(w, x, y, z)` quaternions.
Isaac Lab 3.0 renames the HDR channel to `rgb_hdr`, returns `ProxyArray` buffers, and uses `(x, y, z, w)`.
The adapter maps these differences explicitly. It refuses to run on any version other than 2.3.x unless you set
`allow_untested_isaac=True`. Do not upgrade a working installation for this package.

## 2. Install

```bash
# inside the Isaac Lab Python environment (replace `python` with `${ISAACLAB}/isaaclab.sh -p` if needed)
git clone https://github.com/spikelab-jhu/isaac-sim-event-camera-plugin evis
git -C evis checkout d6fe47923fad09c4bfa2fd2cb13f82520114cfae
python -m pip install --no-deps -e evis          # --no-deps keeps Isaac's numpy/torch
python -m pip install --no-deps -e .
python -m pip install h5py scipy pillow pytest   # usually already present
```

No network access is needed at run time. Scene assets (texture PNG, USD) are generated into `asset_dir`.

## 3. Run order

| Step | Command | What it checks |
|---|---|---|
| 1 | `python -m pytest` | SE(3) integration, limits, safety, packet schema, observation isolation, EVIS core behavior, reference persistence, recording/replay, metrics |
| 2 | `python tests/isaac/acceptance_plane.py` | intrinsics (≤ 0.5 px), depth (≤ 1 mm, center and corners), six-axis signs, render-buffer latency |
| 3 | `python tests/isaac/acceptance_cube.py` | framing, static false-event rate (≤ 0.01 ev/px/s), persistence, temporal convergence (1.0/0.5/0.25 ms), limits, synchronization, schema, replay, first demo |
| 4 | `python experiment.py` | bootstrap + fixed orbit, recorded to `runs/` |

Steps 2 and 3 write `acceptance/acceptance_*.json`. They need separate processes because each builds one scene.

- **Stale frames.** If step 2 reports `latency.stale = true`, increase `renders_per_capture` and rerun. Never relabel old buffers.
- **Static false events.** If step 3 fails its static-scene check, look at the renderer settings reported in `describe.backend.render_settings`. Do not filter the events.
- **GUI vs headless.** Run `experiment.py` once with each setting, then call `recording.compare_episodes(run_a, run_b)`.

## 4. API

```python
from nbm_sim.camera import launch_app
from nbm_sim.config import SimConfig

cfg = SimConfig(scene_id="textured_cube", display=False)
app = launch_app(cfg)                          # before any other Isaac import

from nbm_sim.environment import CameraNBMEnv
env = CameraNBMEnv(cfg)
packet = env.reset(seed=0)
packet = env.step(np.array([0.1, 0, 0, 0, 0, 0]), duration=0.05)
run_dir = env.save_episode()
env.close()
```

| Call | Purpose |
|---|---|
| `env.run_bootstrap(schedule)` | Saved twist schedule before planning; counts toward acquisition cost, not `max_steps` |
| `env.camera_state()` | Known pose, world velocity, path cost, declared target-center prior |
| `env.get_evaluation_state()` | Evaluator-only GT depth/mask and reference geometry |
| `env.get_state()` / `env.set_state(s)` | Pose, controller, clock, EVIS reference, RNG. Renderer history is not captured |
| `env.set_timing(**kw)` | Change clock/limits between episodes |
| `baselines.FixedOrbit / FixedScan / BoundedRandom` | `act(map_state, uncertainty, observation_history, camera_state)` |
| `recording.load_episode / iter_packets / rerun / compare_episodes / write_preview` | Replay without and with re-rendering |
| `evaluation.reconstruction_metrics` | Target-only accuracy, completeness, P/R/F at 2/5/10 mm |
| `interfaces.Reconstructor / UncertaintyModel / Planner / EventPredictor` | Protocols for research modules |

Packet fields follow spec §11.2. Arrays are read-only copies. `actor_view` removes fields the selected
`observation_protocol` does not allow. GT depth, masks and meshes never enter a packet.

## 5. Conventions

| Quantity | Convention |
|---|---|
| World | Right-handed, +Z up, meters |
| Camera optical frame | +X right, +Y down, +Z forward |
| Pose | `T_wc` (optical → world), NumPy 4×4 |
| Command | Body twist `[vx, vy, vz, wx, wy, wz]` in the optical frame, m/s and rad/s |
| Integration | `T ← T · Exp(dt · ξ)` per 1 ms base tick |
| Intrinsics | Pixel-center convention, `cx = (W−1)/2`. Isaac stores `W/2` (edge convention); the adapter converts |
| USD camera | `R_gl = R_wc · diag(1, −1, −1)`, set with `convention="opengl"` and checked by reading back `quat_w_ros` |
| Depth | `distance_to_image_plane`; invalid values → `NaN`, `depth_valid = False` |

**Acceleration limits** act on world-frame velocity between tick endpoints. Inside a tick the body twist is
constant, so world linear velocity turns by `|ω||v|dt`. That turning is subtracted from the linear slew budget.
Config validation rejects limits where `ω_max · v_max ≥ a_max`.

**Safety.** Each tick checks both endpoints against the workspace and the analytic box colliders, with a
margin of half the tick's path length. Because signed distance is 1-Lipschitz, this bounds the whole swept
segment. A rejected tick ends the episode at the last safe state and reports `collision_attempt` or
`workspace_violation` (an idealized emergency stop).

## 6. EVIS event-model behavior (from its source at `d6fe479`)

These facts matter for any future event predictor. `events.package_info()` re-checks them in the installed source
and writes them to every manifest.

| Item | Behavior |
|---|---|
| Brightness | `I = 0.2126 R + 0.7152 G + 0.0722 B` on linear `HdrColor` |
| Log | `log(I + 1e-5)` |
| Firing | `Δlog I ≥ C` → +1, `≤ −C` → −1 |
| Reference update | Set to the **current** `log I` (not `ref ± C`) where the pixel fired |
| Events per pixel per sample | **At most one**. A 5·C jump in one sample gives one event |
| Timestamp | Sample time of the frame (no sub-sample interpolation) |
| First frame / reset | Initializes the reference, emits nothing |

Consequences:

- The spec's "multiple crossings" check (§17) cannot pass with this package as it is. `tests/test_evis_core.py` records the actual behavior instead.
- Event counts depend on the sampling rate until it has converged. The temporal-convergence check measures this.
- A matching predictor must use the same single-event, latch-to-current rule.

The wrapper uses the package's `BatchedMultiCamProcessor` directly. A small in-memory sink stands in for its
HDF5 recorder, so events come back per packet. Accelerated mode uses the package's `bidir_warp_gap`. It feeds
the real keyframe at the end of each gap, so events never cross packet boundaries. Accelerated mode is P2 and untested.

## 8. Known limitations

| Item | State |
|---|---|
| Isaac-side code | Written against the Isaac Lab 2.3.2 and EVIS sources; not yet executed |
| Render settings | Motion blur, DOF and auto-exposure keys are set through `carb`; the read-back values go to the manifest. Key names depend on the renderer version |
| Colliders | Analytic axis-aligned boxes only. Mesh assets (e.g. ficus) need a collider path before use |
| Renderer history | Not part of `get_state()`; a restore re-renders from the restored pose |
| Accelerated mode | Implemented, not validated against reference mode |
| Noise | Off by default. `get_state()` with noise enabled deep-copies the noise model's torch generator, which is untested |
| `num_envs` | 1 |
